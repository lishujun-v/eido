## 一、背景与目标

### 1.1 背景

宠物经济持续升温，养宠人群规模逐年扩大，宠物已从"看家工具"转向"家庭成员"。当前市场上宠物相关产品与服务存在几个明显痛点：

1. **信息分散**：养宠知识散落在各平台，新手难辨真伪，踩坑成本高。
2. **社区与服务割裂**：内容社区（如贴吧、小红书宠物话题）与宠物服务（美容、医疗、寄养）、宠物电商三者各自为政，用户需在多个 App 间切换，体验割裂。
3. **服务非标、信任度低**：上门喂养、寄养等服务缺乏统一评价与保障体系，用户决策成本高。
4. **购物决策缺乏依据**：买粮、买用品时缺少基于宠物真实情况的推荐与真实用户反馈。

### 1.2 目标

打造一个 **"社区 + 服务 + 商城"** 一体化的宠物服务平台，让养宠用户在一个平台内完成"交流学习—预约服务—购买商品"的闭环。

- **业务目标**：
  - 上线 6 个月内积累注册用户 50 万，月活（MAU）10 万。
  - 商城月 GMV 达到 100 万元。
  - 服务订单月均 5000 单。
- **用户目标**：
  - 新手养宠人能快速获取可信知识与服务。
  - 资深宠友有稳定的分享与社交场所。
  - 忙碌养宠人能便捷预约到靠谱服务。
- **产品目标**：
  - 实现社区内容驱动服务与商城转化（内容种草 → 服务/商品成交）。

### 1.3 范围说明

- 本期 PRD 覆盖 Web 端 + 移动端 H5，优先保证移动端体验。
- 不包含独立 App 原生开发（后续视数据再定）。
- 不包含自营供应链与线下门店建设，商城初期以入驻商家模式为主。

## 二、用户画像

### 2.1 画像 A：新手养宠小白

| 维度 | 描述 |
| --- | --- |
| 年龄 | 18-30 岁 |

| 特征 | 知识匮乏、焦虑、爱搜索、易被种草 |

## 三、需求详述

### 3.1 社区模块

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| C-01 | 内容发布 | 支持图文/视频帖子发布，可添加话题标签、宠物标签 |
| C-02 | 内容浏览 | 按推荐流、最新、分类（猫/狗/异宠/医疗/行为等）浏览 |
| C-03 | 互动 | 点赞、评论、收藏、转发、关注作者 |
| C-04 | 问答 | 用户可发布求助/提问帖，他人回答，支持采纳最佳答案 |
| C-05 | 个人主页 | 展示用户发布的帖子、宠物档案、获赞数据 |

### 3.2 服务模块

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| S-01 | 服务分类 | 涵盖美容洗护、医疗、寄养、上门喂养/遛狗、训练等 |
| S-02 | 服务商列表 | 按距离/评分/价格筛选，展示资质、评价、案例 |
| S-03 | 在线预约 | 选择服务、时间、填写宠物信息与特殊需求，在线下单 |
| S-04 | 订单管理 | 查看预约状态、取消/改期、联系服务商 |
| S-05 | 服务评价 | 服务完成后对服务商打分 + 文字评价 |

### 3.3 商城模块

| 编号 | 需求 | 说明 |
| --- | --- |
| M-01 | 商品分类 | 宠粮、零食、用品、玩具、保健、清洁等 |
| M-02 | 商品详情 | 图片、规格、参数、评价、适用宠物类型 |
| M-03 | 购物车与下单 | 加入购物车、选规格、填地址、在线支付 |
| M-04 | 订单管理 | 待付款/待发货/待收货/已完成/退款 |
| M-05 | 商品评价 | 收货后评价，支持图文 |

### 3.4 通用与支撑需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| U-01 | 注册登录 | 手机号 + 验证码、微信登录 |
| U-02 | 宠物档案 | 用户可创建宠物档案（品种、年龄、性别、体重、疫苗记录等），用于精准推荐与服务 |
| U-03 | 搜索 | 全站搜索帖子/商品/服务商 |
| U-04 | 消息中心 | 互动通知、订单通知、系统通知 |
| U-05 | 客服 | 在线客服（在线咨询 + 工单） |

## 五、主要交互流程

### 5.1 新用户注册到首次发帖

1. 打开网站 → 点击「注册」→ 输入手机号 + 验证码（或微信一键登录）→ 设置昵称头像。
2. 引导页选择「你养的宠物」（品种/名字/年龄）→ 生成宠物档案。
3. 进入首页推荐流 → 浏览帖子 → 点击「发布」→ 选择图文 → 添加文字/图片 → 关联宠物标签与话题 → 发布成功 → 跳转帖子详情页。

### 5.2 商品购买流程

1. 首页/搜索进入商城 → 浏览分类或搜索商品 → 进入商品详情页。
2. 选择规格（口味/规格）→ 「加入购物车」或「立即购买」。
3. 确认订单：收货地址、商品、数量、金额 → 选择支付方式 → 支付成功 → 跳转订单详情（待发货）。
4. 商家发货 → 用户收到物流通知 → 确认收货 → 可评价。

### 5.3 服务预约流程

1. 进入「服务」频道 → 选择服务类型（如上门喂养）。
2. 服务商列表按距离/评分筛选 → 进入服务商详情（资质/评价/案例）。
3. 点击「预约」→ 选择服务项目、时间、填写宠物信息与特殊需求 → 确认下单支付。
4. 订单状态流转：待接单 → 已接单 → 服务中 → 服务完成 → 评价。

## 六、验收标准

### 6.1 社区

- 用户可成功发布图文帖，发布后内容可在推荐流/个人主页正确展示。
- 点赞、评论、收藏操作即时生效，数据准确，刷新不丢失。
- 图片上传支持常见格式，单帖最多 9 图，单图 ≤ 10MB。

### 6.2 服务

- 服务商列表筛选条件生效，距离与评分排序正确。
- 预约下单后订单状态正确流转，服务商可接单/完成。
- 服务完成后用户可提交评价，评价展示在服务商详情页。

### 6.3 商城

- 商品分类与搜索结果准确，商品详情页信息完整加载。
- 购物车增删改查正常，价格与库存计算无误。
- 支付流程畅通，支付成功后订单状态正确，支持查看与退款。

### 6.4 通用

- 注册登录流程顺畅，验证码 60s 内到达。
- 宠物档案可创建、编辑、删除，并在发帖/服务/推荐场景正确调用。
- 消息通知准确触达，无漏推/误推。

## 七、非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 首屏加载 ≤ 2s；接口 P95 响应 ≤ 500ms；列表页滑动无明显卡顿 |
| 并发 | 支撑峰值 QPS 2000；秒杀/活动场景需做限流与队列 |
| 兼容性 | 移动端 H5 兼容 iOS 13+/Android 8+ 主流浏览器；Web 端兼容 Chrome/Edge/Safari 最近两个大版本 |
| 安全 | 用户数据加密存储；支付走第三方合规通道；敏感信息脱敏展示；符合《个人信息保护法》 |
| 可用性 | 核心服务可用性 ≥ 99.9%；具备熔断与降级预案 |
| 可扩展性 | 服务模块支持横向扩展服务商类型；商城支持后续接入自营商品 |
| 无障碍 | 关键操作支持键盘可达，图片提供 alt 文本 |

## 九、风险与依赖

| 风险/依赖 | 说明 | 应对 |
| --- | --- | --- |
| 服务商资源 | 初期服务商数量不足影响服务模块体验 | 上线前定向招商，首期聚焦 1-2 个核心城市 |
| 支付资质 | 商城与服务交易依赖支付通道与资质 | 尽早申请资质，接入成熟第三方支付 |
| 内容合规 | UGC 社区存在违规内容风险 | 接入敏感词过滤 + 人工审核 + 举报机制 |
| 冷启动 | 社区初期内容稀薄 | 种子用户运营 + 官方内容填充 + 达人引入 |

## 十、附录

- **术语表**：MVP = 最小可行产品；MAU = 月活跃用户；GMV = 商品交易总额。
- **待确认事项**：是否需要独立 App、是否自营商品、首期目标城市范围——均待业务侧确认后进入 v1.1。
- **后续版本**：v2.0 规划将依据 M6 数据复盘决定，暂定方向为宠物社交匹配、线下活动、宠物保险。
