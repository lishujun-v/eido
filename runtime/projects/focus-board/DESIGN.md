# 专注看板 v2 设计说明

## 设计目标

把现有的轻量三列看板升级为“以日期为中心”的每日执行工具。用户每天只需要确认当天的任务、填写进展和勾选完成；系统负责按需复制下一天任务列表并保留历史进展。

正式项目入口：`index.html`。该标准入口会加载 `design.html` 中的完整看板实现，确保 Projects 容器能够正常初始化权限和存储。

## 核心模型

- **需求**：任务所属的上层事项，用于说明“为什么做”。
- **任务**：会跨天延续的执行单元，包含标题、需求、负责人、优先级和当前状态。
- **每日快照**：某一天任务状态与进展的只读记录。历史不会被后续修改覆盖。
- **每日进展**：按“任务 + 日期”保存；同一任务每天可留下不同记录。

建议的数据关系：

```text
Requirement 1 ── n Task 1 ── n DailyTaskSnapshot
```

## 主视图

1. 顶部仅保留“前一天 / 当前日期 / 后一天”，支持按钮、键盘左右键和触控左右滑动。
2. 主体在宽屏下采用“全部任务”主列与右侧“今日总结”侧栏；窄屏下总结回流到任务表下方。
3. 列顺序固定为：所属需求、任务、优先级、负责人、当日进展、状态。
4. 点击任意单元格即可原地编辑；优先级和状态使用下拉选项，其他字段直接输入。
5. “显示列”菜单可独立隐藏或恢复任意列，显示偏好会随项目数据保存；菜单不会被任务行高度裁切，点击外部区域或按 Esc 自动收起。
6. “所属需求”列表头后的“+”会在全部需求组末尾新增需求并直接编辑需求名称；所属需求单元格内的“+”会在同需求任务组末尾插入并继承需求名称。删除按钮固定显示在最右侧状态单元格末尾，不增加额外操作列，历史日期不展示操作按钮。
7. 同名需求只展示一次，并通过纵向合并单元格覆盖该组全部任务；所属需求前的拖动柄可调整需求组顺序，同需求下的全部任务作为一个整体移动。
8. 工具栏提供 70%～140% 整个项目界面缩放（包含日期导航、工具栏和任务表格）；各列表头右侧提供列宽拖动柄，缩放比例与列宽偏好均随项目数据保存。

## 关键交互

### 新建与编辑任务

- 点击“所属需求”列表头后的“+”，在末尾创建新需求，并直接填写需求名称；空状态仍提供首条任务入口。
- 点击所属需求旁的“+”，在同需求任务组末尾插入任务并立即编辑任务名称。
- 同一需求在所属需求列只渲染一次合并单元格，组内任务始终连续排列；修改需求名称时会同步更新组内全部任务。
- 任务名称前提供矩形完成框；勾选后状态切换为“已完成”，整行标绿并添加删除线，再次点击可恢复。
- 每个单元格都可点击原地修改；失焦或按 Enter 保存，进展文本使用 `Ctrl/Cmd + Enter` 保存。
- 所有文字单元格都支持自动换行和手动换行，编辑框随内容自动增高，任务行同步撑高；使用 `Ctrl/Cmd + Enter` 快速保存多行文字。
- 按住所属需求前的拖动柄上下移动，可重排整个需求组；该需求的全部任务始终一起移动。
- 输入法处于拼音组词状态时，Enter 只确认输入法候选，不会提前提交单元格。
- 优先级和状态用下拉选项，避免自由输入造成数据不一致。
- 优先级和状态不使用悬停弹层；单击对应单元格后直接展开下拉选项，选中目标值后立即保存，避免鼠标移动时误触相邻任务或遗留弹层。
- 历史日期保持只读。

### 每日复制

- 点击“后一天”时，如果目标日期尚不存在，就完整深拷贝当前日期的任务列表。
- 需求、任务、优先级、负责人、当日进展和完成状态等信息均保持一致，仅日期不同。
- 每个日期保存独立任务数组与内部任务 ID；修改新一天的内容不会影响前一天。
- 宽屏时，“今日总结”位于“全部任务”右侧，按“昨日进展 / 风险 / 今日事项”自上而下展示；窄屏时回流到任务列表下方。各项支持多行输入、内容自动增高，并随当前日期独立持久化。
- 历史日期的今日总结只读；首次创建后一天时，会随任务列表一起复制当前日总结，之后两天的数据彼此独立。
- 同一天重复打开不会再次复制，也不会覆盖用户已经在该日期做出的修改。

### 日期切换

- 点击“前一天 / 后一天”。
- 桌面端支持键盘左右方向键。
- 触控端支持在看板空白区域左右滑动；卡片内部滑动不触发换日，避免与任务操作冲突。
- 历史日期为只读快照，防止用户误改过去记录。
- 今天和未来日期可以独立编辑；历史日期只展示该日真实保存的信息，不临时推算任务。

## 必要状态

- **加载状态**：先渲染页面骨架和本地缓存，再同步宿主存储；不因存储等待而显示空白页。
- **空状态**：每列分别说明当前无任务，并提供新建或调整状态的引导。
- **保存反馈**：编辑和完成操作后给出轻量成功提示。
- **存储失败**：保留用户刚填写的内容，显示“未同步，可重试”，不能静默丢失。
- **历史只读**：按钮禁用，同时在日期下方明确标注“历史快照”。
- **未来日期**：标注为独立任务视图，明确修改不会影响前一天。

## 视觉规范

- 背景：`#f7f7fb`
- 主文字：`#202235`
- 次要文字：`#74788d`
- 主色：`#6558d9`
- 边框：`#e5e5ef`
- 成功色：`#238165`
- 卡片圆角：13px；列容器圆角：18px
- 保持白色卡片、低对比边框、轻阴影，避免改成重型项目管理后台。
- 高优先级使用柔和红色，中优先级使用柔和橙色，低优先级沿用绿色，颜色始终配合文字标签，不能只靠颜色传达信息。

## 响应式

- 1140px 以上使用任务主列与右侧纵向总结侧栏；宽屏项目区最大宽度为 1560px，任务主列优先占用剩余空间。850px～1140px 时总结回流至任务表下方并横向排列。
- 850px 以上使用完整六列表格。
- 850px 以下每一行折叠为两列信息卡片，任务标题与当日进展占整行，日期导航保持固定结构。
- 移动端始终显示需求旁的新增入口，任务行底部仍可就地插入。
- 整个项目界面缩放范围为 70%～140%；缩放控件固定在项目界面外，拖动时不会跟随内容位移。拖动期间仅使用合成层预览，松手后再更新布局和占位高度，避免连续重排导致闪屏。桌面表头支持逐列拖动宽度，小屏卡片模式隐藏列宽拖动柄。

## 开发建议

1. 当前实现按日期保存完整任务快照，任务使用稳定 ID，每日进展仅存在于对应日期快照中。
2. 日期统一使用本地时区的 `YYYY-MM-DD` 字符串，避免 UTC 跨日问题。
3. 新一天复制要做成幂等操作：同一天重复打开不能重复生成任务或覆盖已有内容。
4. 当前实现优先读取 `project.storage`。宿主会把数据写入 `runtime/projects/focus-board/data/storage.json`；浏览器本地存储仅作为独立预览、首次迁移和磁盘写入失败时的兜底。
5. 保留任务稳定 ID，快照单独生成 ID，便于查询同一任务的历史轨迹。

## 本轮暂不纳入

- 复杂权限和团队协作通知
- 日历月视图
- 评论、附件、工时统计
- 自动生成进展总结

这些能力会显著增加复杂度，建议等每日使用流程稳定后再评估。
