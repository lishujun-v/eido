# Note Down 产品设计方案

## 1. 产品定位

Note Down 是一个轻量、离线优先的桌面端 Markdown 快速笔记工具。核心目标是让用户打开后立即记录，同时兼顾源码编辑与阅读效果，并将笔记和图片资产明确保存到项目内的 `output` 目录。

首版只解决一件事：快速完成一篇包含 Markdown、链接和图片的笔记，并可靠地保存到本地。

## 2. 目标用户与核心场景

目标用户是需要频繁记录灵感、会议纪要、技术草稿和资料摘要的个人用户。

核心使用流程：

1. 打开应用或新建笔记。
2. 在 Markdown 编辑区输入内容。
3. 在右侧实时查看渲染效果。
4. 粘贴图片并调整显示大小。
5. 选中文字并插入链接。
6. 点击保存，将 `.md` 和图片写入项目的 `output` 目录。

## 3. 信息架构

界面采用三栏结构：

- 左侧笔记栏：新建、搜索、笔记列表、打开输出目录。
- 中间编辑区：Markdown 源码、编辑工具栏、行号与光标状态。
- 右侧预览区：实时渲染结果、图片选择与缩放交互。

顶部工具栏包含：标题级别、粗体、斜体、链接、图片、列表、分割线、代码和保存。

底部状态栏包含：保存状态、文件路径、行列位置、字数和 Markdown 模式。

视觉参考见 `design-assets/note-down-ui-reference.png`。

## 4. 核心功能设计

### 4.1 Markdown 编辑与预览

- 中间区域始终保留 Markdown 源码，避免内容被富文本转换破坏。
- 右侧预览随输入更新，建议使用 150–300ms 防抖。
- 支持 CommonMark 与 GFM 常用语法：标题、列表、任务列表、表格、引用、代码块、删除线和链接。
- 编辑区与预览区可分别滚动；后续版本可增加同步滚动。

### 4.2 图片粘贴与缩放

- 用户在编辑区粘贴剪贴板图片时，图片立即插入当前光标位置。
- 图片保存到当前笔记对应的附件目录，Markdown 中使用相对路径。
- 预览区中的图片可被选中，选中后显示边框、四角控制点和当前宽度。
- 拖动控制点时保持原始宽高比，最小宽度建议为 120px，最大宽度不超过内容区宽度。
- 图片宽度使用兼容 Markdown 的 HTML 表达保存，例如：

```html
<img src="./项目灵感记录.assets/image-001.png" alt="" width="640" />
```

- 建议同时提供“原始大小”“适合内容宽度”和“替换图片”操作。

### 4.3 链接插入

- 选中文字后点击链接按钮，弹出小型输入框填写 URL。
- 未选中文字时，同时填写“显示文字”和“链接地址”。
- 确认后生成标准 Markdown：`[显示文字](https://example.com)`。
- 预览中的外部链接使用新窗口打开，并清晰显示可点击状态。

### 4.4 本地保存

- 主保存入口位于右上角，并支持快捷键 `Cmd/Ctrl + S`。
- 保存成功后，底部状态栏显示：`已保存到 output/文件名.md`。
- 文件名默认取第一个一级标题；没有标题时使用日期时间，如 `note-2026-08-04-153000.md`。
- 文件名需要过滤 `/ \ : * ? " < > |` 等非法字符，重名时提示覆盖或自动追加序号。
- 用户关闭或切换笔记前，如果存在未保存修改，必须给出明确提醒。
- 首版以手动保存为准，可增加本地草稿自动恢复，但不应在未告知的情况下覆盖正式文件。

## 5. 本地文件结构

推荐每篇笔记使用一个 Markdown 文件和同名附件目录：

```text
note-down/
├── output/
│   ├── 项目灵感记录.md
│   ├── 项目灵感记录.assets/
│   │   ├── image-001.png
│   │   └── image-002.jpg
│   └── 会议纪要.md
└── ...
```

这样复制、备份或迁移单篇笔记时关系清晰，Markdown 内的图片路径也保持相对引用。

## 6. 关键交互状态

- 空状态：提示“新建一篇笔记开始记录”，主按钮为“新建笔记”。
- 编辑中：保存按钮可用，状态栏显示“有未保存修改”。
- 保存中：保存按钮显示进行中状态，避免重复提交。
- 保存成功：短暂成功提示，同时更新状态栏路径。
- 保存失败：保留编辑内容，显示失败原因和“重试”。
- 图片选中：显示缩放边框、控制点和尺寸。
- 图片处理失败：保留可恢复提示，不向 Markdown 插入无效路径。
- 外部文件发生变化：提示重新加载或保留当前版本，不能静默覆盖。

## 7. 视觉规范

- 风格：安静、专业、轻量，使用白色和浅灰作为主要背景，蓝色作为唯一主强调色。
- 左侧栏宽度约 260px；编辑区与预览区默认各占剩余空间的一半。
- 编辑与预览之间使用可拖动分隔条，建议最小栏宽 360px。
- 正文字号 14–16px，预览正文行高约 1.7，阅读宽度控制在 65–75 个字符。
- 界面优先通过间距、对齐和分隔线建立层级，减少卡片和阴影。
- 图片选中框使用主蓝色，控制点需有足够点击面积，不应只依赖细小视觉点。

## 8. 快捷键建议

- `Cmd/Ctrl + N`：新建笔记
- `Cmd/Ctrl + S`：保存
- `Cmd/Ctrl + K`：插入链接
- `Cmd/Ctrl + B`：粗体
- `Cmd/Ctrl + I`：斜体
- `Cmd/Ctrl + Shift + P`：切换预览

## 9. 首版范围

首版必须包含：

- Markdown 源码编辑
- GFM 实时预览
- 新建、打开和保存本地笔记
- 粘贴图片并保存为本地附件
- 图片等比缩放并持久化宽度
- 链接插入
- 未保存状态与错误反馈
- 常用快捷键

首版暂不包含：云同步、多人协作、账号系统、标签体系、全文检索、版本历史、插件系统、导出 PDF 和多端同步。

## 10. 技术实现边界建议

后续实现建议采用桌面壳层，以便可靠访问项目文件系统；若使用纯浏览器方案，需要额外处理浏览器文件权限和目录授权。

建议模块边界：

- `Editor`：文本编辑、选区、快捷键和插入语法。
- `MarkdownRenderer`：解析、安全过滤和实时预览。
- `ImageManager`：剪贴板读取、附件命名、存储和缩放元数据。
- `NoteRepository`：新建、读取、保存、重命名和冲突处理。
- `WorkspaceState`：当前笔记、未保存状态、面板尺寸和 UI 状态。

安全要求：渲染 Markdown 内嵌 HTML 时需要防止脚本注入；外部链接必须使用安全的打开方式；文件操作必须限制在授权的项目目录内。

## 11. 验收标准

- 输入 Markdown 后，预览在 300ms 内更新且编辑光标不跳动。
- 粘贴 PNG/JPEG/WebP 图片后，附件实际存在于 `output` 下的对应附件目录。
- 拖动图片控制点可等比缩放，保存并重新打开后尺寸保持不变。
- 插入链接后，源码格式正确，预览可点击。
- 保存后生成可独立阅读的 `.md` 文件，所有图片均使用有效相对路径。
- 保存失败不会丢失当前编辑内容。
- 在常见桌面宽度下，三栏布局不遮挡保存按钮或核心编辑区域。

## 12. 后续实现顺序

1. 建立桌面项目与本地文件访问能力。
2. 完成编辑器、Markdown 渲染和三栏布局。
3. 完成新建、打开、保存与未保存状态。
4. 完成图片粘贴、附件存储、缩放和尺寸持久化。
5. 完成链接插入与快捷键。
6. 补齐异常状态、安全过滤和端到端验收。
