# 数字分身 Agent 平台 UI 设计方案

版本：v0.2

状态：已实施

## 0. 2026 Dashboard 风格重构

本轮以用户提供的后台管理参考图为视觉基准，保留 Eido 的业务结构和交互，仅重构视觉层。

### 参考图分析

- 配色：冷白灰大底、纯白内容卡片、近黑文本，荧光青柠色只承担品牌、选中态和核心动作；避免多种高饱和色竞争。
- 组件：18–24px 大圆角容器，控件偏胶囊形，卡片使用极淡边框和低扩散阴影；图标保持细线性，激活图标使用深色底配青柠前景。
- 排版：标题用高字重和紧字距，正文与辅助信息形成明显灰阶；内容密度较高，但使用 8/12/16/24px 的稳定间距节奏。
- 布局：窄侧栏 + 弹性主工作区 + 固定宽度对话区。大区域比例清晰，卡片在栅格内等高排列。

### 已实施设计令牌

- 页面背景：`#EDF0ED`
- 内容表面：`#FFFFFF`
- 柔和表面：`#F5F6F2`
- 主文本：`#11120F`
- 次级文本：`#5A5E55`
- 弱文本：`#85897E`
- 强调色：`#B9F52B`，高亮态 `#C9FF2F`
- 边框：`#E5E7E0`
- 卡片圆角：16–24px；胶囊控件：999px
- 主阴影：`0 18px 55px rgba(30, 34, 24, 0.07)`

### 组件规则

- 主按钮使用青柠底与近黑文字，次按钮使用白底细边框，导航激活态使用浅青柠底。
- Agent 卡片使用统一深色图标容器，hover 只抬升 2px，避免夸张动效。
- 对话消息保留黑白对比，输入区和信息卡片统一使用同一套表面、边框与圆角令牌。
- 所有可交互控件提供清晰的青柠色键盘焦点环。

## 1. 设计目标

MVP 的 UI 目标是让用户快速建立三个感受：

- 这是一个可信的数字身份平台
- 这里可以通过 Agent 认识真实的人
- 我的隐私和边界是可控的

界面不应该像传统招聘网站、普通社交 App 或纯 AI 工具站。它应该更像一个“可对话的个人主页网络”。

## 2. 产品气质

关键词：

- 可信
- 清晰
- 轻社交
- 现代
- 有一点未来感
- 克制但不冰冷

避免：

- 过度赛博朋克
- 大面积紫蓝渐变
- 过度营销感
- 传统招聘平台感
- 信息过密的后台感
- 太娱乐化的社交软件感

## 3. 视觉方向

### 3.1 总体方向

建议采用“明亮中性色 + 少量高识别强调色”的设计语言。

主界面以浅色为主，强调清晰、开放、可信；深色可以作为局部状态或对话强调，不建议 MVP 默认做暗黑主题。

整体视觉参考方向：

```text
现代个人主页
+ 轻量 SaaS 工具
+ 智能名片
+ 聊天产品
```

### 3.2 色彩建议

基础色：

- 页面背景：#F7F8FA
- 主内容背景：#FFFFFF
- 主文本：#111827
- 次级文本：#4B5563
- 弱文本：#9CA3AF
- 边框：#E5E7EB
- 分割线：#EEF0F3

品牌强调色：

- 主色：#2563EB
- 主色 hover：#1D4ED8
- 浅主色背景：#EFF6FF

辅助色：

- 成功 / 可联系：#16A34A
- 警告 / 待确认：#D97706
- 风险 / 拒绝：#DC2626
- Agent 标识色：#0F766E

使用原则：

- 主色用于主要按钮、链接、当前状态
- Agent 标识色用于“数字代理”标签和 Agent 回复提示
- 警告色用于真人确认、隐私提醒、风险提示
- 页面不要被单一蓝色铺满，保持留白和中性色主导

## 4. 字体与排版

### 4.1 字体

Web MVP 建议：

```css
font-family: Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
```

中文系统会自然回退到系统中文字体。

### 4.2 字号层级

页面标题：

- 32px / 40px / 700

二级标题：

- 24px / 32px / 700

区块标题：

- 18px / 28px / 600

正文：

- 15px / 24px / 400

辅助文本：

- 13px / 20px / 400

标签文字：

- 12px / 18px / 500

### 4.3 排版原则

- 表单和后台页面保持紧凑
- Agent 主页可以更舒展
- 搜索结果页强调扫描效率
- 对话页重点保证消息可读性
- 不使用过大的标题塞进卡片或紧凑面板

## 5. 布局系统

### 5.1 页面宽度

建议：

- 首页主体最大宽度：1120px
- Agent 主页最大宽度：960px
- 后台最大宽度：1200px
- 对话页最大宽度：1040px

### 5.2 间距

基础间距单位：4px

常用间距：

- 4px
- 8px
- 12px
- 16px
- 24px
- 32px
- 48px
- 64px

### 5.3 圆角

建议：

- 小控件：6px
- 卡片：8px
- 输入框：8px
- 弹窗：10px
- 头像：圆形

不要大量使用超大圆角，避免显得像娱乐化消费 App。

### 5.4 阴影

默认少用阴影，主要靠边框和背景层级。

建议：

- 普通卡片：1px 边框，无阴影
- 悬浮卡片：轻微阴影
- 弹窗：中等阴影

## 6. 核心组件风格

### 6.1 按钮

Primary：

- 蓝底白字
- 用于核心动作：创建 Agent、发布、发起对话、接入对话

Secondary：

- 白底灰边框深色文字
- 用于次要动作：预览、返回、查看主页

Ghost：

- 透明背景
- 用于导航、轻操作

Danger：

- 红色文字或红色边框
- 用于举报、拉黑、删除

按钮高度：

- 普通：40px
- 大按钮：48px
- 小按钮：32px

### 6.2 输入框

风格：

- 白底
- 1px 灰色边框
- 8px 圆角
- focus 时蓝色描边

搜索框可更突出：

- 高度 56px
- 左侧搜索图标
- 右侧搜索按钮
- 支持自然语言长输入

### 6.3 标签 Badge

类型：

- 技能标签
- 城市标签
- 数字代理标签
- 可联系状态
- 匹配原因标签
- 风险状态标签

样式：

- 技能标签：浅灰底
- 数字代理：浅青色底
- 可联系：浅绿底
- 待确认：浅黄底
- 风险：浅红底

### 6.4 卡片

Agent 卡片结构：

```text
头像 + 名称 + 状态
一句话介绍
能力标签
城市 / 职业
匹配原因
操作按钮
```

卡片原则：

- 不嵌套卡片
- 8px 圆角
- 1px 边框
- hover 时边框变深或轻微阴影

### 6.5 状态提示

状态需要清楚但不刺眼：

- 可联系：绿色点 + 可联系
- 忙碌：黄色点 + 忙碌
- 暂停：灰色点 + 暂停接收请求
- 真人已接入：蓝色提示条
- 等待主人确认：黄色提示条
- 对话已关闭：灰色提示条

## 7. Agent 视觉语言

### 7.1 数字代理标识

每个 Agent 页面和对话中都应有稳定标识：

```text
数字代理
```

建议样式：

- 浅青色背景
- 青绿色文字
- 小圆点或芯片样式

作用：

- 明确当前不是直接和真人本人对话
- 建立产品独特识别
- 降低误代表风险

### 7.2 Agent 头像

MVP 可支持：

- 用户上传头像
- 默认渐变头像
- 首字母头像

默认头像不要太机械化。Agent 虽然是数字代理，但背后是人，头像应该更接近个人身份而不是机器人图标。

### 7.3 真人接入标识

当主人接入后，需要明显区分：

- Agent 消息
- 真人主人消息
- 系统提示

建议：

- Agent 消息：左侧，浅青色辅助标识
- 访问者消息：右侧，浅蓝或白底
- 真人主人消息：左侧，带“本人”标签
- 系统消息：居中灰色小提示

## 8. 关键页面 UI 方向

### 8.1 首页

目标：

让用户第一眼知道这是一个“通过 Agent 找人和被找到”的平台。

布局：

```text
顶部导航
主标题
副标题
大搜索框
创建 Agent 按钮
热门标签
推荐 Agent
```

视觉建议：

- 第一屏不要做传统营销大图
- 搜索框是第一视觉中心
- 创建 Agent 是第二核心动作
- 推荐 Agent 卡片露出真实使用场景

首页标题建议：

```text
让世界通过 Agent 认识你
```

副标题建议：

```text
创建你的数字分身，或用一句话找到你想认识的人。
```

### 8.2 创建 Agent 页面

目标：

降低填写压力，让用户觉得是在“塑造自己的数字身份”，而不是填一份冗长简历。

布局：

```text
左侧步骤导航
右侧表单主体
底部操作按钮
```

设计重点：

- 每一步只聚焦一类问题
- 表单说明要短
- 示例占位文案要具体
- 资料完整度用进度条展示
- 预览发布页要给用户成就感

表单风格：

- 简洁
- 分组清楚
- 多用标签输入和开关
- 少用大段说明文字

### 8.3 Agent 公开主页

目标：

像一个可信的“可对话个人主页”。

布局：

```text
顶部身份区
能力与服务区
经历和作品区
想认识的人
沟通风格
发起对话固定入口
```

设计重点：

- 顶部要有强身份感
- 能力标签要明显
- “发起对话”按钮始终容易找到
- 隐私信息不要空占位
- 明确提示 Agent 是数字代理

主页顶部结构：

```text
头像
名称
数字代理标签
城市 / 职业 / 状态
一句话介绍
[发起对话]
```

### 8.4 搜索结果页

目标：

让用户快速判断谁可能合适。

布局：

```text
顶部搜索框
需求解析条
左侧过滤器
右侧结果列表
```

设计重点：

- 匹配原因必须可见
- Agent 卡片信息要易扫
- 不要把搜索结果做成社交信息流
- 空结果要引导用户放宽条件

### 8.5 Agent 对话页

目标：

让用户感觉是在和一个可靠代理初步沟通，而不是随便和 AI 聊天。

布局：

```text
顶部对话对象信息
身份提示条
消息区
快捷问题
输入区
真人接入状态条
```

设计重点：

- 首屏清楚声明数字代理身份
- 消息气泡要区分 Agent / 访问者 / 本人 / 系统
- 真人接入状态要非常清楚
- 输入区不要被太多按钮干扰

### 8.6 我的 Agent 后台

目标：

让主人管理自己的数字分身和待处理请求。

布局：

```text
左侧侧边栏
右侧内容区
```

设计重点：

- 后台要工作台化，不要营销化
- 待处理请求要突出
- Agent 状态和公开主页链接要容易找到
- 隐私和行为边界要让用户有控制感

## 9. 关键 UI 状态

### 9.1 Agent 可联系状态

```text
绿色点 可联系
黄色点 忙碌
灰色点 暂停接收请求
```

### 9.2 真人接入状态

```text
等待主人确认
主人已接入
主人已拒绝
Agent 将继续沟通
```

### 9.3 隐私状态

```text
公开
登录后可见
匹配后可见
主人确认后可见
私密
```

### 9.4 风险状态

```text
普通
需要确认
高风险
已拦截
```

## 10. 图标建议

建议使用 lucide-react 图标。

常用图标：

- Search：搜索
- UserRound：用户
- Bot：数字代理
- MessageCircle：对话
- ShieldCheck：安全 / 可信
- Lock：隐私
- Eye：可见性
- Bell：通知
- Handshake：合作
- MapPin：城市
- Tags：能力标签
- AlertTriangle：风险
- Ban：拉黑
- Flag：举报
- CheckCircle：可联系 / 成功

图标使用原则：

- 按钮中优先使用图标 + 简短文字
- 工具型按钮可只用图标，但需要 tooltip
- 不手写 SVG 图标

## 11. 移动端原则

移动端重点：

- 首页搜索框优先
- Agent 主页 CTA 固定在底部
- 搜索结果单列展示
- 对话页输入框固定底部
- 后台侧边栏改成顶部 Tabs 或抽屉

最小适配宽度：

- 360px

移动端不要出现：

- 文字挤出按钮
- 卡片横向滚动
- 固定侧边栏遮挡内容
- 对话输入框遮挡最后一条消息

## 12. 首批高保真页面优先级

建议先设计这 3 个页面：

1. 首页
2. Agent 公开主页
3. Agent 对话页

原因：

- 首页决定用户是否理解产品
- Agent 主页决定用户是否愿意创建和分享
- 对话页决定 Agent 体验是否成立

第二批：

1. 创建 Agent 流程
2. 搜索结果页
3. 我的 Agent 后台

## 13. 设计验收标准

UI 第一版需要满足：

- 用户能一眼理解这是数字分身平台
- Agent 和真人身份区分清楚
- 公开主页足够值得分享
- 搜索结果能快速扫描
- 对话页有可信感，不像普通 AI 聊天页
- 隐私和真人确认机制可见但不吓人
- 页面在移动端不拥挤、不重叠

## 14. 下一步

建议直接进入项目初始化，并在开发中优先实现这套 UI 基础：

1. 设计 tokens：颜色、字号、间距、圆角
2. 基础组件：按钮、输入框、标签、卡片、提示条
3. 业务组件：AgentCard、AgentStatusBadge、DigitalAgentBadge、ChatThread
4. 首屏页面：首页、Agent 公开主页、Agent 对话页

如果需要更视觉化的探索，可以再单独生成 3 个首页视觉方向，选一个作为最终风格。但从 MVP 速度看，现在这份 UI 方案已经足够开始开发。
